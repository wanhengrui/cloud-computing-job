# Lab1B: static three-node DHT for the ride service

Lab1A kept every order in one process's `unordered_map`. Lab1B replaces that
map with a three-node key/value ring while the customer-facing contract
(`CreateRide` / `GetTrip`) stays byte-for-byte identical.

```
ride_client --> trip-service --> pricing-service          (unchanged from 1A)
                     |
                     +--> DHT Put("trip:<id>", <Trip protobuf bytes>)
                     +--> DHT Get("trip:<id>")  --> ParseFromString
                                |
                        node-a -> node-b -> node-c   (static successor ring)
```

## What is in here

| path | purpose |
| --- | --- |
| `proto/dht.proto` | generic KV contract: `Put` / `Get`, `hops`, `path` |
| `src/dht_common.h` | FNV-1a 32, `(predecessor, self]` interval test, inventory loader |
| `src/dht_service.{h,cc}` | one ring node: owns, stores, or forwards exactly one hop |
| `src/dht_node_server.cc` | reads `SELF` + `NODE_A/B/C_*` from the environment |
| `src/dht_cli.cc` | `--entry` client used to start requests at a non-owner node |
| `src/trip_service.{h,cc}` | 1A handler with the local map replaced by DHT calls |
| `config/` | local ring yaml (container names, `selector_name: domain`) |
| `config/cloud/` | generated by `scripts/gen-cloud-config.sh` (private IPs, `direct`) |
| `scripts/` | `up.sh`, `verify.sh`, `fault-test.sh`, `gen-cloud-config.sh`, `down.sh` |
| `env/node-inventory.example.env` | the course inventory shape, never commit the real one |

## Ring design (decisions worth defending)

- **Hash**: FNV-1a 32. Deterministic, dependency free, short enough to
  re-derive by hand during the defence.
- **node_id**: `FNV1a32("node-a") = 79934867`, `node-b = 96712486`,
  `node-c = 113490105`. Ascending id order is also the name order, so the ring
  runs `node-a -> node-b -> node-c -> node-a`.
- **Ownership**: node `N` owns `(predecessor_id, N.id]`. When `N` has the
  smallest id the interval wraps, which is the case the code spells out:
  `pred > self ? (hash > pred || hash <= self) : (hash > pred && hash <= self)`.
- **Forwarding**: a non-owner forwards only to its successor and increments
  `hops`. The entry node starts at `hops = 0`, so a three-node ring needs at
  most 2 hops; `hops >= 3` aborts with an explicit error. That limit is a
  configuration guard rail, **not** fault tolerance.
- **Two hop records per request**: every node logs
  `action=serve|forward ... hops=<n> path=node-a->node-b`, so the report can
  show the same key taking different routes from different entries.
- **Threading**: `io_handle_type: separate` + `handle_thread_num: 4`. With
  `merge`, the handler that blocks on the downstream RPC also owns the event
  loop; 1A deadlocked exactly that way (`ThreadHeartBeat TimeOut`) and 1B would
  reproduce it because trip-service now makes two sequential downstream calls.
- **Selectors**: `domain` locally (targets are container names), `direct` on the
  CVMs (targets are private IP literals). 1A proved `direct` returns an empty
  endpoint for host names and `domain` is the only thing that resolves them.

## Quick start (one laptop, Docker Desktop / WSL2)

```bash
cd lab1b          # repo layout: cloud-computing-job/lab1b
                  # on the author's laptop the same tree lives at 云计算/lab1-b/project
bash scripts/up.sh          # build + start pricing, trip, dht-a/b/c
bash scripts/verify.sh      # 23 checks: ring coverage, hops, 41.04 / 17.20
bash scripts/fault-test.sh  # stop node-b, observe, restart
bash scripts/down.sh
```

Manual poking at the ring:

```bash
export MSYS_NO_PATHCONV=1   # Git Bash only: stop /app/... being rewritten
docker run --rm --network lab1b_ridenet lab1b-dht-microservices:local \
  /app/dht_cli --op=put --key=lab1b:key41 --value=hello --entry=node-a
# put_ok=1 owner=node-c hops=2 message=value stored on node-c (path node-a->node-b->node-c, hops 2)

docker run --rm --network lab1b_ridenet lab1b-dht-microservices:local \
  /app/dht_cli --op=get --key=lab1b:key41 --entry=node-b
# found=1 owner=node-c hops=1 message=value read from node-c (path node-b->node-c, hops 1)
```

## Cloud deployment (three CVMs)

1. Fill `env/node-inventory.env` from the example (private IPs, same ids).
2. `bash scripts/gen-cloud-config.sh` writes `config/cloud/*.yaml`.
3. On each host, run the same image with that host's yaml and the inventory:

```bash
docker run -d --name dht --network host \
  -e SELF=node-b \
  $(sed 's/^/-e /' config/cloud/node-inventory.env | tr '\n' ' ') \
  lab1b-dht-microservices:local /app/dht_server --config=/app/config/cloud/dht-node-b.yaml
```

Port 19001 is the only port that has to be open between the three hosts.
`trip-service` + `pricing-service` run wherever it is convenient (this plan
puts them on node-b) and reach the ring through the private IPs.

## Known limits (state them in the report)

- No replication and no repair: losing the owner loses the key. The fault test
  shows `found=0` after the owner restarts, because the node keeps its store
  in memory.
- No dynamic join/leave: the ring is a static three-entry list.
- No finger table: routing is deliberately one successor hop at a time.
- `dht_cli` values are opaque bytes; order values are protobuf and print as
  `<n bytes>`.
